title: Commands
description: Create custom commands for repetitive tasks.
---

Custom commands let you specify a prompt you want to run when that command is executed in the TUI.

```bash frame="none"
/my-command
```

Custom commands are in addition to the built-in commands like `/init`, `/undo`, `/redo`, `/share`, `/help`. [Learn more](/docs/tui#commands).

---

## Create command files

Create markdown files in the `commands/` directory to define custom commands.

Create `.opencode/commands/test.md`:

```md title=".opencode/commands/test.md"
---
description: Run tests with coverage
agent: build
model: anthropic/claude-3-5-sonnet-20241022
---

Run the full test suite with coverage report and show any failures.
Focus on the failing tests and suggest fixes.
```

The frontmatter defines command properties. The content becomes the template.

Use the command by typing `/` followed by the command name.

```bash frame="none"
"/test"
```

---

## Configure

You can add custom commands through the OpenCode config or by creating markdown files in the `commands/` directory.

---

### JSON

Use the `commands` option in your OpenCode [config](/docs/config):

```json title="opencode.jsonc" {4-12}
{
  "$schema": "https://opencode.ai/config.json",
  "commands": {
    // This becomes the name of the command
    "test": {
      // This is the prompt that will be sent to the LLM
      "template": "Run the full test suite with coverage report and show any failures.\nFocus on the failing tests and suggest fixes.",
      // This is shown as the description in the TUI
      "description": "Run tests with coverage",
      "agent": "build",
      "model": "anthropic/claude-3-5-sonnet-20241022"
    }
  }
}
```

Now you can run this command in the TUI:

```bash frame="none"
/test
```

---

### Markdown

You can also define commands using markdown files. Place them in:

- Global: `~/.config/opencode/commands/`
- Per-project: `.opencode/commands/`

```markdown title="~/.config/opencode/commands/test.md"
---
description: Run tests with coverage
agent: build
model: anthropic/claude-3-5-sonnet-20241022
---

Run the full test suite with coverage report and show any failures.
Focus on the failing tests and suggest fixes.
```

The markdown file name becomes the command name. For example, `test.md` lets
you run:

```bash frame="none"
/test
```

## Prompt config

The prompts for the custom commands support several special placeholders and syntax.

---

### Arguments

Pass arguments to commands using the `$ARGUMENTS` placeholder.

```md title=".opencode/commands/component.md"
---
description: Create a new component
---

Create a new React component named $ARGUMENTS with TypeScript support.
Include proper typing and basic structure.
```

Run the command with arguments:

```bash frame="none"
/component Button
```

And `$ARGUMENTS` will be replaced with `Button`.

You can also access individual arguments using positional parameters:

- `$1` - First argument
- `$2` - Second argument
- `$3` - Third argument
- And so on...

The highest-numbered placeholder includes any remaining arguments.

For example:

```md title=".opencode/commands/create-file.md"
---
description: Create a new file with content
---

Create a file named $1 in the directory $2
with the following content: $3
```

Run the command:

```bash frame="none"
/create-file config.json src '{ "key": "value" }'
```

This replaces:

- `$1` with `config.json`
- `$2` with `src`
- `$3` with `{ "key": "value" }`

---

### Shell output

Use _!`command`_ to inject [bash command](/docs/tui#bash-commands) output into your prompt.

For example, to create a custom command that analyzes test coverage:

```md title=".opencode/commands/analyze-coverage.md"
---
description: Analyze test coverage
---

Here are the current test results:
!`npm test`

Based on these results, suggest improvements to increase coverage.
```

Or to review recent changes:

```md title=".opencode/commands/review-changes.md"
---
description: Review recent changes
---

Recent git commits:
!`git log --oneline -10`

Review these changes and suggest any improvements.
```

Shell interpolation runs in the session's working directory, which may be a subdirectory of your project, and its output becomes part of the prompt.
It finishes before the command prompt is submitted, including commands that run a background subagent.

---

### Mentions and attachments

Mentions such as `@src/components/Button.tsx` or `@reviewer` in command templates remain literal plain text in the prompt for the model and tools to interpret:

```md title=".opencode/commands/review-component.md"
---
description: Review component
---

Review the component in @src/components/Button.tsx.
Check for performance issues and suggest improvements.
```

Command templates do not automatically synthesize file or agent attachments from mention text. When invoking a command, any explicit attachments provided in the prompt composer or API are preserved and forwarded directly to the session or subagent.

## Options

Let's look at the configuration options in detail.

---

### Template

The `template` option defines the prompt that will be sent to the LLM when the command is executed.

```json title="opencode.json"
{
  "commands": {
    "test": {
      "template": "Run the full test suite with coverage report and show any failures.\nFocus on the failing tests and suggest fixes."
    }
  }
}
```

This is a **required** config option.

---

### Description

Use the `description` option to provide a brief description of what the command does.

```json title="opencode.json"
{
  "commands": {
    "test": {
      "template": "Run tests with coverage",
      "description": "Run tests with coverage"
    }
  }
}
```

This is shown as the description in the TUI when you type in the command.

---

### Agent

Use the `agent` config to optionally specify which [agent](/docs/agents) should execute this command.
If this is a [subagent](/docs/agents/#subagents) the command will trigger a background subagent invocation by default.
To disable this behavior and run in the parent session instead, set `subagent` to `false`.

```json title="opencode.json"
{
  "commands": {
    "review": {
      "template": "Review $ARGUMENTS",
      "agent": "plan"
    }
  }
}
```

This is an **optional** config option. If not specified, defaults to your current agent.
For commands that run in the parent session, specifying `agent` switches the session's selected agent. Later prompts continue using that agent until you switch it again.

---

### Subagent

Use the `subagent` boolean (or legacy alias `subtask`) to force the command to trigger a background [subagent](/docs/agents/#subagents) invocation.
This runs the command prompt in a background child session. The parent keeps its selected agent and model and receives a completion notice containing the child's result when done.

```json title="opencode.json"
{
  "commands": {
    "analyze": {
      "template": "Analyze $ARGUMENTS",
      "subagent": true
    }
  }
}
```

:::note
In native `commands` config or Markdown frontmatter, use `subagent: true` (or legacy alias `subtask: true`). For legacy `command` config (singular), use `subtask: true`.
:::

This is an **optional** config option.

When both `subagent` and `subtask` are present in native config or Markdown frontmatter, `subagent` takes precedence, including `false`. Setting it to `false` runs in the parent session, switching the parent's agent and model when specified by the command.

---

### Model

Use the `model` config to select the model for this command.
The command's `model` takes precedence over the configured model of its specified `agent`.
If neither supplies a model, a parent command keeps the current session model; a child command uses the selected agent's model, falling back to the parent model.
For commands that run in the parent session, selecting a model changes the session's selected model for later prompts too.
Background child commands select their own agent and model and keep the parent's selections unchanged.

```json title="opencode.json"
{
  "commands": {
    "analyze": {
      "template": "Analyze $ARGUMENTS",
      "model": "anthropic/claude-3-5-sonnet-20241022"
    }
  }
}
```

This is an **optional** config option.

---

## Built-in

opencode includes several built-in commands like `/init`, `/undo`, `/redo`, `/share`, `/help`; [learn more](/docs/tui#commands).

:::note
Custom commands can override built-in commands.
:::

If you define a custom command with the same name, it will override the built-in command.
